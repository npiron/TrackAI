# Title: Observation v2 (option obs_version=2), v1 intacte par défaut

## Goal
Donner à l'agent une vue plus riche (volant réel, ligne centrale à venir, courbure, lidars plus longs) pour rouler sans choc sur des pistes jamais vues (étape 1 du goal), sans changer la physique.

## Acceptance criteria
- [ ] `TimeAttackEnv(..., obs_version=1)` et `GymTimeAttack(..., obs_version=1)` : défaut 1 = observation actuelle, 14 valeurs, strictement identique (test sur un épisode : mêmes obs qu'avant).
- [ ] `obs_version=2` : vecteur de taille fixe documenté dans le docstring, composé de : les 9 premières valeurs de v1 inchangées aux mêmes indices (0-8) ; `car.steering` (position réelle du volant, dans [-1,1], dont l'ancien `prev_steer` reste en 4) ; pour les 5 prochains points de la ligne centrale (`track.spline_points`, à partir de l'indice le plus proche de la voiture, espacés d'une distance d'arc fixe, p.ex. 40 px, circulaires) : distance normalisée et angle (sin, cos) dans le repère de la voiture ; courbure à venir (changement de cap moyen entre points, normalisé, ≥ 1 valeur) ; 9 lidars (angles de -π/2 à π/2 par pas de π/8) avec portée plus longue (≥ 300 px, normalisée dans [0,1]). `observation_space` a la bonne forme ; toutes les valeurs finies.
- [ ] La physique (`Car`, `step`) n'est pas modifiée ; `cast_rays_jit` sert aux deux versions (portée en paramètre, v1 garde 150).
- [ ] Le professeur heuristique reste utilisable : `heuristic_action(obs, ta)` ne lit que obs[0], obs[3], obs[6], obs[7], obs[11] (v1). En v2, documenter dans le docstring de `heuristic_action` que l'appelant doit passer une obs v1 (méthode `ta.obs_v1()` exposée, qui renvoie l'obs v1 courante), et ajouter ce test.
- [ ] Tests dans `tests/test_env.py` : forme v1 = 14, forme v2 = N annoncé, finitude sur 200 pas d'actions aléatoires en procédural, points de ligne centrale : sur une ligne droite connue le 1er point est devant (angle ≈ 0), `ta.obs_v1()` égal à l'obs v1 d'un env v1 jumeau.
